# start_stack コマンドビルダー

*[English version here](README.md)*

*コードを書いたことがない方向けに、スクリーンショット付きの平易な解説 [GETTING_STARTED.md](GETTING_STARTED.md)（英語）もあります。*

`start_stack` の起動コマンドをフラグを覚えずに組み立てるためのローカルツールです。同じオプションとロジックを共有する2つのインターフェースがあります。

- **Web UI**（Flask）— コマンドを組み立ててコピーできる画面
- **TUI**（ターミナルウィザード）— コマンドラインだけで操作できる対話形式

どちらも次の形のコマンドを組み立てます — 各フラグが1行ずつ改行され、行末に `\` が付くので、シェルに貼り付けても1つのコマンドとして実行できます。

```
start_stack \
  --vehicle_name truck-807 \
  --launch_config sds_road_readiness \
  --route shoreline_terminal_10kph \
  --enable_japan_driving
```

`route`・`enable_japan_driving` は任意項目です（未設定の場合はコマンドから丸ごと省かれます）。`vehicle_name` と `launch_config` は必須項目です。`--map_key` フラグもマップ選択画面も存在しません — ルート自体がマップ情報を持つため、`--route` だけで十分です（複数のマップで同名のルートが使われている場合は `map_name:route_name` の形で出力されます）。UI 上では代わりに、ルート一覧がマップごとにグループ化されて表示されます。

## セットアップ

初回実行には `flask`・`questionary`・`pyperclip` をインストールした Python の仮想環境が必要です。3つの起動スクリプトはどれもこれを自動で行います — `venv/` がまだ無ければ作成し、起動前に `pip install -r requirements.txt` を実行します。

## 実行方法

プロジェクトディレクトリで以下を実行します。

```
./run.sh        # Web UI。起動後 http://127.0.0.1:5050 を開く
./launch.sh     # ターミナルウィザード
./recorder.sh   # コマンドウィザードなしで画面録画だけ行う
```

初めて `./launch.sh` を実行すると、シェルの設定ファイルに `launch` エイリアスが自動的に追加されます（zsh の場合は `.zshrc`、bash の場合は macOS では `.bash_profile`、Linux では `.bashrc`/`.bash_aliases`）。これにより、以降はこのディレクトリに移動しなくても、どこからでも `launch` と入力するだけで起動できます。`./recorder.sh` も同様に `recorder` エイリアスを追加します。エイリアスを有効にするには、新しいターミナルを開くか、表示されたファイルを `source` してください。シェルを自動検出できなかった場合は、自分で追加すべきエイリアスの行がそのまま表示されます。

## Web UI

ドロップダウンから値を選び、**コマンドを作成** ボタンを押すと `start_stack` コマンドが表示され、クリップボードにコピーするボタンも使えます。

- **車両名（vehicle_name）** はサジェスト付きのテキストボックスです — 入力を始めると（`807` でも `truck-807` でも動きます）候補が絞り込まれ、クリックして一覧から選ぶこともできます。数字だけを入力した場合は `truck-<数字>` に組み立てられます。
- **ルート（route）** のドロップダウンには、すべてのルートが属するマップごとにグループ化されて表示されます（ルート自体がマップ情報を持つため、マップ選択は不要です — 詳細は下記「[オプションの取得元](#オプションの取得元)」を参照）。
- 右上の **日本語 / English** リンクで画面の表示言語を切り替えられます。言語を切り替えるとフォームはデフォルト状態にリセットされ（他の選択内容は引き継がれません）、**日本語** を選んだ場合は `enable_japan_driving`（日本走行モードを有効化）にあらかじめチェックが入ります（外すことも可能です）。
- **プリセット** を保存している場合、フォームの上にドロップダウンと **読み込む** ボタンが表示され、選んで押すだけでプリセットがすぐに使えます — 値プリセットはコマンドに組み立てられ、カスタムコマンドプリセットはそのまま表示され、結果は自動的にクリップボードにコピーされます（フォームを埋め直す必要はありません）。ドロップダウンから1つを選んで **プリセットを削除** ボタンを押すと削除できます（どちらのボタンもプリセットが選ばれているときだけ有効になります）。メインフォームでは、**プリセット名** を入れて **プリセットとして保存** を押すと現在の選択内容を保存でき、**カスタムコマンド** 欄に任意のコマンドを貼り付けて **カスタムコマンドをプリセットとして保存** を押すとそのまま保存できます。
- **最近のコマンド** には、これまでに組み立てたコマンド（Web UI と TUI で共通の履歴です）が一覧表示され、それぞれにコピーボタンが付いています。以前のコマンドを再コピーするためにフォームをもう一度埋め直す必要はありません。

## TUI

`./launch.sh` を実行し、矢印キーと Enter で各質問に答えていきます。最初の画面以降はすべて `<< 戻る` で前の質問に戻れ、`終了` でいつでもキャンセルできます（Ctrl+C でも終了します）。

手順は以下の順番です。

1. **言語（Language）** — English または 日本語。以降のすべての表示文言と `enable_japan_driving` のデフォルト値（下記参照）に影響します。
2. **何をしますか？** — このメニューは常に表示されます。**新しいコマンドを作成** で通常のウィザードに進みます。**画面録画のみ** ならコマンド作成をスキップして録画に直行します（`./recorder.sh` と同じフローで、選んだ言語で表示されます）。**トラックから最新の実行IDを取得** は、ケーブル接続中のトラックから最新の run id を取得し（下記「[トラックから最新の実行ID（Run ID）を取得](#トラックから最新の実行idrun-idを取得)」を参照）、クリップボードにコピーしてメニューに戻ります。**トラックのSSHをセットアップ（トラックごとに1回）** は、トラックごとのSSHセットアップ（鍵とエイリアスはトラック番号の名前。下記「[トラックごとのSSHセットアップ](#トラックごとのsshセットアップ共有ip問題の解決)」を参照）を行い、メニューに戻ります。**カスタムコマンドをプリセットとして保存** は、このツールで組み立てたものではない任意のコマンドを、そのまま実行できる形で名前を付けて保存します（先頭の `$` プロンプト記号や `\` による複数行形式は自動的に整形されます）。保存済みのプリセットや最近のコマンドは、作成した時点でこのメニューに加わります。どれかを選ぶと、コマンドが表示され、クリップボードにコピーされた後、手動で組み立てたコマンドと同じ録画の確認が続きます（スキップされるのは「プリセットとして保存」の確認だけです — すでに保存済みのためです）。**プリセットを削除**（プリセットがある場合に表示）は1つを選んで確認して削除し、その後メニューに戻ります。現在のオプションに存在しなくなった値（brain2 から削除されたルートなど）は注記付きで除外されます。
3. **車両名（vehicle_name）** — 入力すると検索できます。数字を入力し始めると該当するトラックが候補に表示されます。数字だけを入力すると（例: `807`）、`truck-807` の形に組み立てられます。数字の代わりに `back` または `quit` と入力して画面移動することもできます。
4. **起動設定（launch_config）** — 利用可能な4つの設定の一覧です。English を選んだ場合は `sds_road_readiness` が先頭に、日本語を選んだ場合は `etc_sds_road_readiness` が先頭に表示されます。
5. **ルート（route・任意）** — すべてのルートがマップごとに整理して表示されます。複数のマップで同名のルートが使われている場合は `route_name (map_name)` の形で表示され、区別できます。
6. **日本走行モードを有効化（enable_japan_driving）** — はい/いいえ。English を選んだ場合はデフォルトで **いいえ**、日本語を選んだ場合はデフォルトで **はい** になりますが、どちらを選んでも変更可能です。

最後にコマンドがターミナルに表示され、クリップボードが使える環境であれば自動的にコピーされます。手動で組み立てたコマンドの場合、その後 **選択内容をプリセットとして保存するか** 尋ねられます — 名前を付けて保存すれば、次回は1ステップで再構築できます。

### 前回の選択を記憶します

車両番号と起動設定の選択内容はローカルの `.launch_state.json`（gitでは管理されません）に保存され、次回 `./launch.sh` を実行したときにデフォルト値として表示されます。変更したくない項目はそのまま Enter を押すだけで構いません。起動設定は **言語ごとに別々に** 記憶されます（English での前回選択と日本語での前回選択はそれぞれ独立して保持されます）。同じファイルには **プリセット** と直近20件の **組み立て済みコマンド** の履歴も保存され、これがプリセット・最近のコマンドのショートカット（および Web UI のプリセットと履歴の表示）の正体です。この保存は最後まで完了した実行の後にのみ行われ、途中で終了した場合は何も保存されません。

## 画面録画

コマンドが作成されクリップボードにコピーされた後、この実行の画面を録画するかどうか尋ねられます。内部でどのツールが使われるかはマシンによって自動的に選ばれます。

| マシン | キャプチャツール |
| --- | --- |
| macOS | ffmpeg の `avfoundation` |
| Linux・X11 | ffmpeg の `x11grab` |
| Linux・Wayland（KDE/GNOME） | `gpu-screen-recorder` |
| Linux・Wayland（Sway・Hyprland などの wlroots 系） | `wf-recorder` |

不足しているツールは、対応するパッケージマネージャーが見つかれば自動的にインストールされます（macOS では Homebrew、Linux では apt・dnf・pacman — Debian でも Arch でもそのまま動作します）。自動インストールに失敗した場合（例: `gpu-screen-recorder` がそのディストリビューションにパッケージされていない場合）は録画がスキップされ、何をどうインストールすべきかが表示されます。Linux の Wayland では、マシンごとの最初の録画時に画面共有の承認ダイアログが表示されることがあります — 承認すると録画が始まります。

全体はキー1つで操作します（テキスト入力の場面以外は Enter 不要です）：

1. **`r`** を押すと録画開始、**`q`** を押すと録画をせずにスキップします。
2. 録画が始まると、ターミナルには `● Recording... 00:07 (press 's' to stop)` のように1秒ごとに増えるタイマー表示が出るので、実際に録画中であることが分かります。テストを実行し、終わったら **`s`** を押して停止してください。
3. **保存するか破棄するか** を聞かれます。**`k`** を押せば保存して続行、**`d`** を押せばその場でファイルを削除して終了します（名前の入力プロンプトには進みません）。
4. 保存を選んだ場合、トラックから最新の run id を取得するかどうかを Yes/No で尋ねます（この選択は記憶され、次回のデフォルトになります）。Yes なら、ケーブル接続中のトラックから取得し、車両・ホスト名・run id・完全なログパス・警告を表示してから次に進みます（次のプロンプトで `back` と入力すると、取得した run id をデフォルト値として再入力できます）。No の場合 — または取得に失敗した場合 — は手動貼り付けのプロンプトになります（任意 — 空欄のまま Enter でスキップ）。
5. **Polarion のテストケース ID** の入力を求められます。ID を入力するか、次のいずれかを入力できます。
   - `back` — run-id の入力からやり直す
   - `skip`（または何も入力せず Enter）— このテストケース ID は無しにする
6. 動画は `~/screen_recordings/<今日の日付>/` に `<タイムスタンプ>_<vehicle_name>_run-<run-id>_tc-<テストケース ID>.mp4` という名前で保存されます（スキップした項目は名前から省かれます）。同名の `.json` サイドカーファイルには、run-id・テストケース ID・Polarion リンク・`start_stack` コマンド・録画時間が記録されます。
7. その直後に **「録画フォルダを開く」** というリンクが表示されます。クリックできるリンクに対応したターミナル（iTerm2・VS Code・kitty・最近の Terminal.app など）であれば、クリックするだけでその日付のフォルダを Finder で直接開けます。フォルダの実際のパスもその上に必ず表示されます。

テストケース ID のプロンプトで `skip` を選ぶと、その選択が記憶され、次回の録画でもデフォルトで `skip` になります（毎回断る必要はありません）。実際のテストケース ID を入力すると、デフォルトはそちらに切り替わります。

Polarion リンクは `recorder.py` 内の URL テンプレート（`POLARION_URL_TEMPLATE`、または環境変数 `POLARION_URL_TEMPLATE`）から組み立てられます — 実際の Polarion サーバーを指すように編集してください（プレースホルダーのままでは実在するリンクになりません）。録画の保存先も環境変数 `RECORDINGS_DIR` で変更できます（デフォルトは `~/screen_recordings`）。

### コマンドウィザードなしで録画する

`start_stack` コマンドを組み立てずに録画だけしたい場合は、ウィザードの最初のメニューで **画面録画のみ** を選ぶか、`./recorder.sh`（エイリアス設定後は `recorder`）を実行してください。どちらも上記と同じ `r` で開始・`s` で停止・保存または破棄・名前入力の流れにそのまま進みます（動画ファイル名に車両名が含まれない点だけが異なります。ウィザードからの選択時は選んだ言語で表示されます）。`skip` の記憶や前回のテストケース ID は、通常のウィザードと共通の状態として扱われます。

## トラックから最新の実行ID（Run ID）を取得

ラップトップをテストトラックにケーブル接続しているとき、どのインターフェースからでも、トラックのログディスクから最新の run id を直接取得できます。

- スタンドアロンのスクリプト — `./truck.sh [車両番号]`。初回実行時にエイリアスが自動追加されるので（`launch`/`recorder` と同じ）、以降はどこからでも `truck` だけで実行できます。run id・完全なログパス・トラックのホスト名を表示し、トラックに接続できない場合は理由を示して終了コード 1 で終わります。
- TUI ウィザード — 最初のメニューの **トラックから最新の実行IDを取得**。同じ情報を表示し、run id をクリップボードにコピーして、メニューに戻ります。記憶されている車両番号も一緒に渡すため、設定済みのエイリアスがあればそれが使われます。
- Web UI — フォーム下の **トラックから実行IDを取得** ボタン（フォームの車両欄は照合用で、取得した run id はコピーボタン付きで表示されます）。
- 録画フロー — 録画を保存した後の **トラックから最新の run id を取得するかどうか** の Yes/No トグル（他の録画時の選択と同じように記憶されます）。録画時の車両名も取得に引き継がれます。

接続先は SSH ターゲット（デフォルト `applied@192.168.1.11`）が指すトラックです。トラックはホスト名（例: `truck-805-primarypc`）で自分の車両番号を名乗るため、取得側は接続しているのがどの車両かを把握します。ログの配置は `/media/hotswap1/frontier/truck-<番号>/<年>/<月>/<日>/<run_id>` で、トラックの時計での「今日」の最新ランを優先します（今日まだない場合は全体の最新を使い、警告を表示します）。

裏では、Master Checklist アプリの取得ボタンと同じ固定の読み取り専用スクリプト（`ls | sort | tail -1`）を、システムの `ssh`（`BatchMode=yes` なのでパスワード入力で止まりません）経由で実行します — 認証はあなた自身の `~/.ssh` の鍵が担い、UI からの入力がシェルに渡ることは一切なく、往復は最長10秒で打ち切られます。

### トラックごとのSSHセットアップ（共有IP問題の解決）

どのトラックも同じ `TRUCK_SSH_TARGET` で応答するため、2台目以降はホスト鍵が違って `ssh 192.168.1.11` が拒否されるようになります。**トラックのSSHをセットアップ** が1台につき1回だけこれを解決します。鍵と `Host` エイリアスは**トラック番号の名前になるよう強制**され、入力はトラック番号だけです：

1. `ssh-keygen -t ed25519 -f ~/.ssh/truck-805` — トラックごとに1つの鍵、パスフレーズなし、0600。
2. `~/.ssh/config` に `Host truck-805` ブロック（専用の `IdentityFile` と
   `UserKnownHostsFile` = `~/.ssh/known_hosts.d/truck-805`）。べき等 — 再実行は
   「すでに存在」と報告します。
3. 公開鍵をトラックにインストール — まず既存の鍵/エージェントで、失敗したら
   トラックのログインパスワードで（必要なときだけ尋ね、`SSH_ASKPASS` 経由。
   パスワードがコマンドラインに現れることはなく、この1回のためだけに使われます）。
   失敗した場合は、手動で実行する `ssh-copy-id` の1行が表示されます。

実行場所:

- `truck setup 805` — スタンドアロンのCLI（`--json` 対応。パスワードは既存の鍵が
  拒否されたときだけ `getpass` で尋ねます）。
- TUI ウィザード — 最初のメニューの **トラックのSSHをセットアップ（トラックごとに1回）**。
  トラック番号を尋ね、結果を表示してメニューに戻ります。
- Web UI — **トラックのSSHをセットアップ** ボタン（フォームの車両欄の番号を使います）。

実行後、その車両番号の取得は生のアドレスではなく `truck-805` にSSHします — 取得系の
インターフェースはどのトラックでもそのまま動き、普通の `ssh truck-805` もどの
ターミナルからでも使えます。

| 環境変数 | デフォルト | 用途 |
| --- | --- | --- |
| `TRUCK_SSH_TARGET` | `applied@192.168.1.11` | ケーブル接続中のトラックへのSSH接続先 |
| `TRUCK_LOG_ROOT` | `/media/hotswap1/frontier` | トラック上のログルート |
| `TRUCK_SSH_BIN` | `ssh` | 呼び出すSSHバイナリ（テスト用のfake sshに差し替えるためのもの） |
| `TRUCK_KEYGEN_BIN` | `ssh-keygen` | セットアップ用のssh-keygenバイナリ（テスト用フック） |
| `TRUCK_SSH_DIR` | `~/.ssh` | 鍵・config・known_hosts.dを置くディレクトリ（テスト用フック） |

`python3 truck.py [車両番号] [--json]` が取得の、`python3 truck.py setup <車両番号> [--json]` がセットアップの元となるCLIです — `--json` は機械可読な出力を表示します（エラーも含み、その場合は終了コード 1）。`truck.py` は標準ライブラリのみで動くため、venv なしで実行できます。

## オプションの取得元

- **車両と起動設定** は常に `options.csv` から取得されます（下記「[オプションの編集](#オプションの編集)」を参照）。
- **ルート** は、brain2 のチェックアウトが利用可能な場合はそこからライブに読み込まれます。`onroad/config/constants/behavior/routes/` 以下のすべての `*.txtpb` ファイル（サブディレクトリも再帰的に走査するため、すべてのマップのルートファイルがファイルの置き場所に依存せず取得されます）から `identifier { map_name, route_name }` のペアが読み取られるため、一覧が brain2 に対して古くなることはありません。各ルートは UI でグループ化するためのマップ情報も持ちます。チェックアウトの場所は環境変数 `BRAIN2_REPO_PATH` で指定できます（未設定の場合は `~/brain2` と `~/Projects/brain2` を順に試します）。
- チェックアウトが見つからない場合は、**`options.csv` の `route` 行にフォールバック** します — ツールはエラーで止まらず、CSV のデータで動作し続けます。
- どちらの場合も、CSV のルート行の `nickname` 列は、名前が一致するライブ取得ルートに引き継がれるため、「Shoreline Terminal - Slow」のような表示名はそのまま機能します。

## オプションの編集

車両と起動設定の値は `options.csv` に定義されています。1行につき1つのオプションを持つ単一のテーブルで、以下の列があります。

| 列 | 意味 |
| --- | --- |
| `field` | どの一覧に属するか: `vehicle_name`・`launch_config`・`route` のいずれか（`route` 行は brain2 のフォールバック兼 nickname の上書き定義として機能します — 上記参照） |
| `value` | `start_stack` に実際に渡される値 |
| `nickname` | 表示用のわかりやすい名前（任意）。空欄の場合は `value` がそのまま表示される |
| `owner_map_key` | **ルート専用** — このルートが属するマップ。UI でルート一覧をグループ化するために使われる |

新しい車両や設定を追加するには、行を追加するだけです。例えば:

```
vehicle_name,truck-831,
```

コードの変更は不要です — Web UI と TUI のどちらも、実行のたびにこのファイルを読み直します。ただし、ルートは CSV の編集すら不要です — brain2 から取得されます（上記「[オプションの取得元](#オプションの取得元)」を参照）。

## テスト

```
./venv/bin/pip install -r requirements-dev.txt
./venv/bin/python -m pytest
```

コマンドビルダー、オプション読み込み（brain2 のライブ取得、CSV へのフォールバック、nickname の上書きを含む）、状態/履歴/プリセット、録画のキャプチャバックエンド検出とファイル名・サイドカー処理、トラック run id 取得（スクリプト生成・出力パース・fake `ssh` バイナリを使った SSH 往復）、モックで駆動する TUI ウィザードのエンドツーエンドテスト、そして Flask のテストクライアント経由での Web UI をカバーしています。
